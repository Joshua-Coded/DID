What is a DID?

A Decentralised Identifier (DID) is a globally unique identifier that does not require a centralised registration authority. The controller proves ownership using a private key.

All DIDs follow this structure:

did:<method>:<method-specific-id> -- Examples -- did:key:z6MkhaXgBZDvotDkL5257faiztiGiC2QtKLGpbnnEGta2doY did:ethr:sepolia:0x03fdd57adec3d438ea237fe46b33ee1e016eda6b did:web:example.com
DID Document Structure
{ "@context": ["https://www.w3.org/ns/did/v1"], "id": "did:key:z6Mk...", "verificationMethod": [{ "id": "did:key:z6Mk...#z6Mk...", "type": "Ed25519VerificationKey2020", "controller": "did:key:z6Mk...", "publicKeyMultibase": "z6Mk..." }], "authentication": ["did:key:z6Mk...#z6Mk..."] }
DID Methods
Method Description Requires Blockchain
did:key Key material encoded directly in the DID. Self-contained, no network lookup needed. No
did:ethr Ethereum-based. Supports key rotation and attribute updates on-chain. Yes — Ethereum
did:web DID Document served at a well-known HTTPS path on your domain. No — DNS / HTTPS
did:jwk JSON Web Key encoded in the DID string. Compact and self-contained. No
did:peer Private peer-to-peer identifiers. Not published to any registry. No
did:ion Bitcoin Layer 2 (Sidetree). High throughput, anchored to Bitcoin. Yes — Bitcoin
Veramo CLI

A framework for managing DIDs and Verifiable Credentials. Configured via agent.yml. Keys stored in database.sqlite.

$ veramo --version
Universal Resolver

A hosted API that resolves DIDs across all major methods. No local setup needed. Configured in your agent.yml.

GET https://dev.uniresolver.io/1.0/identifiers/{did}

Installation & Agent Setup
1
Install Veramo CLI globally
This installs the veramo command on your machine. The -g flag makes it available from any directory.
Terminal
$ npm i @veramo/cli -g
This may take 1–2 minutes. You will see npm download progress.
2
Verify installation
Confirm Veramo installed correctly. You should see a version number like 7.x.x.
Terminal
$ veramo --version Expected output: 7.0.0
3
Create a project folder
All Veramo files — your config, database, and keys — will live in this folder.
Terminal
$ mkdir my-did-project $ cd my-did-project
4
Generate the agent configuration
This creates your agent.yml file — the configuration for your local DID agent. It sets up the key manager, DID providers (including did:ethr:sepolia), and the SQLite database.
Terminal
$ veramo config create
After this runs, you will have agent.yml and database.sqlite in your folder. Your agent is ready.
5
Confirm the config is valid
Terminal
$ veramo config check
What was created?
FilePurpose
agent.yml Your agent configuration. Defines DID methods, key management, database path, and REST server settings.
database.sqlite Local encrypted database storing your private keys, DIDs, and credentials. Keep this file safe — losing it means losing access to your DIDs.

Create and Manage DIDs
1
Create a did:key DID
Instant creation — no blockchain, no network. The identifier is derived directly from the public key.
Terminal
$ veramo did create --provider did:key
Output: a new DID beginning with did:key:z6Mk...
2
Create a did:ethr:sepolia DID
Creates an Ethereum-based DID on the Sepolia testnet. The DID is derived from the Ethereum address.
Terminal
$ veramo did create --provider did:ethr:sepolia
3
Create a did:jwk DID
Terminal
$ veramo did create --provider did:jwk
4
List all your DIDs
Shows every DID stored in your local Veramo database.
Terminal
$ veramo did list
5
Resolve a DID locally via Veramo
Replace the DID below with one you created above. Veramo fetches and displays the full DID Document.
Terminal — replace with your DID
$ veramo did resolve did:key:z6MkhaXgBZDvotDkL5257faiztiGiC2QtKLGpbnnEGta2doY
What happened?

When veramo did create ran, Veramo:

  1. Generated a new cryptographic key pair (Ed25519 or Secp256k1)
  2. Stored the private key in database.sqlite
  3. Derived a unique DID from the public key
  4. Constructed the DID Document
The database.sqlite file contains your private keys. Back it up and keep it secure. In production, keys are stored in an HSM or secure enclave — never in a plain file.

Verifiable Credentials — Trust Triangle

      

        
RoleWhoAction

        

          Issuer
          University, employer, government
          Creates and signs the credential using their DID's private key
        

        

          Holder
          Student, employee, citizen
          Receives and stores the credential in a wallet
        

        

          Verifier
          Another employer, a website, a service
          Resolves the issuer's DID, fetches the public key, checks the signature
        

      

    


    

      
Issue and Verify a Credential

      


        

          
1

          

            
Create credential.json

            
Save this file in your working directory. Replace both DIDs with your own from the Create DID exercise.

            

              

                credential.json
                
              

              
{
  "@context": ["https://www.w3.org/2018/credentials/v1"],
  "type": ["VerifiableCredential"],
  "issuer": { "id": "YOUR_ISSUER_DID" },
  "issuanceDate": "2025-01-01T00:00:00Z",
  "credentialSubject": {
    "id": "YOUR_SUBJECT_DID",
    "name": "Alice Smith",
    "course": "Decentralised Identity 101",
    "grade": "Pass"
  }
}

            

          

        


        

          
2

          

            
Issue the credential

            
Veramo signs the credential with the issuer DID's private key and outputs a JWT.

            

              

                Terminal
                
              

              
$ veramo credential create --json-arg credential.json

            

            
Output: a signed JWT beginning with eyJhbGci...

          

        


        

          
3

          

            
Verify the credential

            
Veramo resolves the issuer DID, retrieves the public key from the DID Document, and checks the cryptographic signature.

            

              

                Terminal — replace <jwt> with your output
                
              

              
$ veramo credential verify --jwt <jwt>

            

          

        


        

          
4

          

            
List all stored credentials

            

              

                Terminal
                
              

              
$ veramo credential list

            

          

        


        

          
5

          

            
Inspect the JWT at jwt.io

            
A JWT is three Base64-encoded sections separated by dots: header.payload.signature. Paste your credential JWT at jwt.io to decode it.
